## Risks / Unknowns

- **Native no-activate/click-through regression risk is the single biggest risk in this plan.** M10's evidence log (`DEVELOPMENT_BUILD_PLAN.md`) records three real defects introduced by the notch's own slide-in animation alone (open/collapse flicker loop, unclickable cells during a transition, a sporadic single collapse from a `GetClientRect` failure path). The notice banner is new visible, clickable, animated surface added to the same window. It must reuse the exact region-reporting/refresh pattern in `OverlayWindow.axaml.cs` (`GetInteractiveRegions`, `AddRegion`, `RefreshRegions`, `InteractiveRegionsChanged`) rather than inventing a parallel mechanism, and `scripts/Test-OverlayBehavior.ps1` must still pass afterward. This needs a real interactive Windows session; it cannot be verified by the automated build/test sequence alone.
- **Unknown: exact wording and one-line format for the copy-usage-summary text.** The example given ("Claude Code - session 42% (resets in 3h), weekly 18%") implies one line per window, joined; the implementer should base it on `QuotaWindowRow`'s existing `Label`/`UsedText`/`ResetText` fields rather than inventing new formatting logic, and must exclude `AccountScope.Partition` and any raw credential/session data.
- **Unknown: whether the two new threshold controls warrant a new `SettingsSection.Alerts` or belong inside the existing `Appearance` section.** The plan defaults to a new section (matches the existing one-concern-per-section pattern and the delegating instructions' "Settings > Providers (or a new Alerts section)" phrasing); record the final decision in the Log when M2 starts.
- **Unknown: precise crossing-detection semantics.** "First crosses ... in the current session" needs a state machine per provider (e.g. `Normal -> Caution` and `Caution -> Exhausted` each fire once, and dropping back below re-arms the next crossing). Implement this as a small pure function/record next to `SeverityThresholds` in `OverlayPresentation.cs` (testable without a window), not embedded directly in view-model code.
- **Version number for the release is a guess (`0.2.0`).** The project has shipped only patch releases (`0.1.0`-`0.1.6`) to date; this is the first release that is a feature addition rather than a fix, so a minor bump seems right, but confirm before tagging.
- **`dotnet-verifier`** should run after each milestone per `.docs/rules/verification.md`; this plan assumes that agent (or the equivalent manual command sequence) is invoked by the implementer, not embedded here as literal shell commands per milestone beyond naming the exact sequence once.
- Clipboard access in Avalonia 11 goes through `TopLevel.GetTopLevel(control)?.Clipboard`; no existing code in this repository uses the clipboard today, so this is new integration surface, not a documented pattern to copy from.
